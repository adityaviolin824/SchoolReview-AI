## Findings

### P2 - API report finalization has one category-failure review-gate edge case

Evidence:

- `backend/school_safety_validator/pipeline.py:201` to `backend/school_safety_validator/pipeline.py:203` can mark the pipeline as requiring human review from failed sections.
- `backend/school_safety_validator/api/inspection_api_routes.py:262` to `backend/school_safety_validator/api/inspection_api_routes.py:272` treats an empty itemized review list as fully reviewed.
- `backend/school_safety_validator/api/inspection_api_routes.py:275` to `backend/school_safety_validator/api/inspection_api_routes.py:284` uses itemized review records to choose `ready_for_report`.
- `backend/school_safety_validator/api/inspection_api_routes.py:710` blocks finalization only when itemized review records are not all reviewed.

Impact:

If a category-level failure produces `failed_sections` but no image-level review item, the UI can proceed to Reports without a human-review decision. This should be uncommon with normal demo inputs, because image-level failures already create review items.

MVP advice:

Not a demo blocker. If you want one small hardening fix later, add a synthetic review item for category-level failures or block finalization when `record.result.human_review_required` is true but review coverage is empty.

### P3 - Partial-category demos will look intentionally conservative

Evidence:

- Frontend initializes only `classroom` as selected in `frontend/src/hooks/useInspectionRun.ts:47` to `frontend/src/hooks/useInspectionRun.ts:58`.
- Backend final aggregation requires all configured categories for a complete verdict in `backend/school_safety_validator/final_verdict_aggregation.py:19`.
- Missing configured categories floor the verdict to `insufficient_evidence` in `backend/school_safety_validator/final_verdict_aggregation.py:215` to `backend/school_safety_validator/final_verdict_aggregation.py:222`.

Impact:

A simple one-category demo will probably generate a successful but conservative report with not-inspected categories and `insufficient_evidence`.

MVP advice:

This is acceptable. For the video, either select/upload all categories or narrate that the tool refuses to issue a stronger verdict from partial evidence.

### P3 - Batch upload state can be stale after partial server-side upload failure

Evidence:

- `frontend/src/hooks/useInspectionRun.ts:307` to `frontend/src/hooks/useInspectionRun.ts:323` uploads all selected files with `Promise.all`.
- The hook refreshes status only after the whole batch succeeds.
- If one upload succeeds and another fails server-side, the accepted file can exist on the backend while the frontend does not append it locally or refresh status in the catch path.

Impact:

This is only likely if a mixed batch includes a file that passes frontend checks but fails backend readability/content-type validation. The user can recover by refreshing status or uploading files one at a time.

MVP advice:

For the demo, upload known-good images. A later small improvement would be to call `refreshStatus()` in the catch path after upload failure.

Impact:

No current failure. Future dependency updates may require maintenance.

MVP advice:

Do not spend demo time here.
